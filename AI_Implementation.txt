## 12. Autonomous AI Planning — The Heart of MONOLITH

The primary interaction of MONOLITH should be natural-language planning.

The user should NOT have to manually create every project, task, milestone, recurring event, or calendar entry.

They should be able to describe their commitments and intentions in ordinary language, and the application should organize their entire workspace automatically.

### Natural-language input

Allow the user to describe multiple commitments, projects, deadlines, and routines in one message.

Example:

"I have an online class every Wednesday for the next 40 days. I need to finish my university project within 10 days. It will take around 8 hours, and I prefer working in shorter sessions. I also want to study Agentic AI every Saturday. Keep my workload manageable."

### AI interpretation

The AI must identify:
- Recurring commitments.
- Recurrence start and end dates.
- One-time events.
- Projects and their deadlines.
- Estimated work durations.
- Individual tasks and milestones.
- Preferred working days.
- Scheduling constraints.
- Missing information and ambiguities.

The AI should convert the message into structured, validated data rather than immediately modifying the calendar.

Ask clarification questions only when necessary. Do not repeatedly ask for information that already exists in the user's profile or calendar.

### Automatic project creation

When the user describes a project:
1. Create the project automatically.
2. Break it into sensible milestones and manageable tasks.
3. Estimate individual task durations when enough information exists.
4. Clearly distinguish user-provided estimates from AI-generated estimates.
5. Establish the deadline and priority.
6. Send the tasks to the scheduling engine.

Allow the user to edit the breakdown before approval.

### Automatic calendar generation

The scheduling engine should:
1. Read existing calendar commitments.
2. Expand recurring events into individual date occurrences.
3. Identify available time slots.
4. Schedule flexible project and study tasks.
5. Distribute workloads realistically.
6. Respect task dependencies and deadlines.
7. Preserve existing fixed commitments.
8. Calculate projected completion dates.
9. Report unscheduled tasks and conflicts.

Do not let the AI invent available time slots or bypass scheduling constraints.

### Workspace synchronization

Once a plan is approved, update all relevant application sections together:

- Calendar: add scheduled events.
- Projects: create or update projects.
- Tasks: create individual work items.
- Courses: update lecture sessions and progress.
- Milestones: establish deadlines and checkpoints.
- Overview: update upcoming work and workload indicators.

All sections must reference the same underlying records. Avoid duplicated or disconnected data.

### Conversational plan modification

The AI must understand follow-up instructions in the context of existing plans.

Examples:
- "Move my project work to Thursday."
- "I can't study this Saturday."
- "Make Fridays free."
- "Finish this project three days earlier."
- "I've completed lecture three."
- "Reduce my workload next week."

Modify only the affected parts of the schedule unless a wider recalculation is necessary.

### Plan preview and approval

Before applying a generated plan, show an attractive scheduling preview.

Include:
- Newly created projects.
- Tasks and milestones.
- Recurring commitments.
- Proposed calendar assignments.
- Expected completion dates.
- Potential conflicts.
- Unscheduled work.

Provide actions to approve, edit, or reject the proposal.

Support a configurable option for automatically applying low-risk changes in the future, but require confirmation for significant changes.

### Adaptive planning

After approval, the application must continue monitoring the consistency of the schedule against task completion and changing commitments.

When the user misses an activity, changes availability, completes work early, or introduces a new deadline, recalculate affected future activities.

Never silently erase completed work or move fixed commitments.

The AI planning experience should feel like having a personal scheduling assistant who understands the entire state of the user's life inside MONOLITH.


## 13. Advanced AI Intelligence, Tool Calling & Autonomous Execution

The AI assistant must be a functional operator of MONOLITH, not merely a conversational interface that generates suggestions.

It should understand the user's intentions, inspect the current application state, invoke appropriate application functions, evaluate their results, and execute authorized changes.

### A. AI prompt engineering

Design and implement a comprehensive prompt architecture for MONOLITH.

Do not rely on a single generic system prompt.

Implement dedicated instructions for:
- Natural-language planning.
- Project and course breakdown.
- Calendar modification.
- Rescheduling and conflict resolution.
- Progress analysis.
- General questions about the user's existing plans.

The prompts must define the assistant's role, responsibilities, scheduling rules, application capabilities, tool usage, safety boundaries, and expected output formats.

Use structured schemas for AI-generated plans and tool arguments.

Keep prompts modular and maintainable in dedicated files.

Include:
- Context-aware prompt construction.
- Ambiguity detection.
- Clarification handling.
- Structured output validation.
- Invalid response handling and controlled retries.
- Model-independent prompt design where possible.

The assistant must never invent information about the user's existing calendar, projects, or progress.

### B. Application tool calling

Give the AI access to actual backend application functions.

Implement tools for operations such as:

- Reading calendar events and availability.
- Inspecting projects, courses, tasks, and milestones.
- Creating and updating projects.
- Creating, updating, and deleting tasks.
- Creating recurring commitments.
- Completing or skipping activities.
- Modifying user availability.
- Requesting task rescheduling.
- Recalculating affected schedules.
- Inspecting scheduling conflicts.
- Retrieving project progress and estimated completion dates.

These tools must connect to real application services and persistent database records.

Do not implement simulated tool calls or functions that merely return hardcoded responses.

The AI should select and invoke the appropriate tools based on the user's request, inspect their results, and continue the interaction when additional operations are necessary.

### C. Autonomous execution

Support configurable levels of AI autonomy:

1. Suggestion mode: The assistant proposes changes and waits for approval.
2. Assisted autonomy: The assistant executes safe, low-risk operations automatically and requests approval for significant changes.
3. Full autonomy: The assistant executes authorized operations within user-defined permissions and scheduling constraints.

The default should be assisted autonomy.

The assistant must distinguish between reversible routine changes and destructive or consequential actions.

Always require confirmation before destructive operations or changes that could significantly affect existing commitments.

The assistant must report what it actually changed, including unsuccessful operations.

### D. Intelligent context management

The assistant must understand follow-up messages in the context of the current conversation and the actual application state.

Maintain a clear distinction between:

- Recent conversation context.
- Persistent user preferences.
- Existing application records.
- Pending scheduling proposals.
- Approved plans.
- Completed and historical activities.

Retrieve current database information before making decisions that depend on existing plans.

Resolve references such as "that task", "the second lecture", and "tomorrow's session" using available context.

Do not create duplicate records when the user is referring to something that already exists.

### E. Scheduling and execution safeguards

All calendar modifications must go through the application's validated backend services and deterministic scheduling engine.

Never allow the AI to bypass scheduling rules by directly writing arbitrary event times.

Implement:
- Input validation for every tool.
- Duplicate-action prevention.
- Transactional updates for related records.
- Recovery from interrupted operations.
- Clear operation success and failure states.
- An audit trail of AI-performed modifications.
- Preservation of completed activities and fixed commitments.

Only report an operation as successful after receiving confirmation from the backend.

### F. Provider and model compatibility

Build a provider-independent integration layer for Gemini and OpenRouter.

Check whether the selected model supports the structured output and tool-calling capabilities required by MONOLITH.

Do not assume every model supports the same features.

Handle unsupported tool calling, malformed outputs, API failures, rate limits, authentication errors, and quota exhaustion gracefully.

Keep API keys secure on the backend and never expose them to frontend code.

The application must remain functional without an AI provider configured.

### G. End-to-end autonomous workflow

Verify the complete workflow:

1. The user sends a natural-language instruction.
2. The AI interprets the request and retrieves relevant application context.
3. The AI identifies the necessary actions.
4. It invokes the appropriate backend tools.
5. The backend validates the requested changes.
6. The scheduling engine determines valid calendar assignments.
7. The application previews or applies changes according to the user's autonomy settings.
8. The database is updated consistently.
9. The AI reports the actual outcome.

Test multi-step requests, follow-up modifications, ambiguous instructions, scheduling conflicts, failed operations, and duplicate-action scenarios.

**Final requirement:** MONOLITH's AI must be capable of genuinely operating the application through controlled tools. It must not be limited to generating plans, explaining schedules, or returning conversational text.
