BLOCKERS
 B1 +--+ Confirmed first-hand | scheduler.py:685-691:
      Chained single-session tasks pack onto the SAME day ("unless the task is
      not splittable" comment inverts Rule 12). Result: 20-course blocks land
      on 3 Saturdays (7/7/6) instead of 1 block per Saturday. Directly
      violates instructions.txt:194-199 (Scenario A) and Rule 12.
      Test A passes only because it asserts weekday()==5, not cadence.
 B2 +--+ Confirmed first-hand | routers/schedule.py:33: dedupe set built only
      from preserved rows where locked is truthy, but completed/skipped/past
      preserved rows are locked=0, while run_schedule re-emits them as
      locked=True (scheduler.py:747). Every /schedule/apply and /regenerate
      re-inserts another copy of every completed/past block: clutter,
      double-counted daily capacity, inflated diffs.
 B3  API key leaks: GET /settings returns ai_api_key plaintext
      (routers/settings.py:7-9) and GET /export embeds it (db.export_all).
      instructions.txt:265 requires keys stay server-side.
      Also invalid CORS combo: allow_origins=["*"] + allow_credentials=True
      (main.py:8-14).

MAJOR FUNCTIONAL GAPS (spec features still missing or half-built)
 G1  Pre-commitment free time unreachable: scheduler.py:464-467/541-544 seeds
      day_last_end from ALL blocked intervals; a 09:00-10:00 gap before a
      10:00 class can never be filled. Underuses commitment days.
 G2  TasksView cannot EDIT tasks (api.tasks.update dead code); no UI for
      preferred_start/preferred_end (model supports, scheduler uses), no
      inputs for min/max session minutes (state exists, no controls);
      dependency dropdown allows self-cycle; no overdue /
      dependency-waiting row indicators.
 G3  generate-sessions endpoint (routers/projects.py): start_date accepted
      but ignored; deadline stamped onto EVERY session (whole course forced
      before one date); estimated_weeks == block_count (frequency unused);
      repeated POST duplicates the whole chain (no idempotence).
 G4  Skip semantics: skipped blocks stay as ghosts on the calendar AND the
      engine re-books the minutes on next regen; skip refunds nothing.
 G5  Editing a commitment leaves stale locked blocks for the old time; next
      regen double-books both old and new. db.update_commitment never touches
      schedule_blocks.
 G6  Timezone wiring dead: settings.timezone and default_session_minutes are
      stored but read by nothing (spec 3.E wants them). reschedule-missed
      compares naive-local timestamps against a UTC-aware "now" as strings —
      wrong "missed" marking for any negative UTC offset. Mixed clocks
      (local date.today() vs UTC parse_dt) inside one engine run.
 G7  Clarification loop broken at both ends: (a) frontend REFINE button is a
      stale-closure bug — the typed answer never reaches /ai/extract
      (CommandBar.tsx:167-172); (b) backend clarifications are a passive
      string list nothing consumes (ai/offline_parser.py:216-222).
 G8  "Preview on Calendar" is misleading: it previews a regen of the CURRENT
      db, ignoring the pending proposal (CommandBar.tsx:62-71). Proposal
      cards are the only true preview.
 G9  Month view fetch window starts 2 weeks before current week — the first
      1-2 weeks of the month grid can render empty; month header row also
      sits inside a 6-row grid (layout spill).
 G10 Fake telemetry presented as real: Waybar "72% DAY COMPLETED" is a
      hardcoded initializer that goes stale; "CPU 12% | RAM 4.2G" invented
      (App.tsx:19, Waybar.tsx:150-152). Spec: "no buttons/objects that only
      look functional".
